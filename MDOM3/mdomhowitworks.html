How It Works

How HIPAA Email from MDOfficeMail Works

Majority of healthcare providers and patients use free email service or the one provided by the internet or web hosting service provider. Connection to most of these services is standard, unencrypted/unsecured (HTTP) and the servers may not be secure. Meaning any sensitive information like PHI sent using these email services can be intercepted and stolen.

HIPAA doesn’t prohibit using email as a medium for sending/receiving Protected Health Information (PHI) in spite of this potential threat. However, by setting up standards it has ensured that the security of patient information via email-based communication is not compromised.

MDOfficeMail has implemented these standards in their services and is fully compliant with HIPAA policies by following recommended procedures aimed at maintaining the integrity of PHI by restricting unwarranted access.

$1.5M

Maximum penalty per HIPAA violation under the HITECH Act (up from $250,000 before 2010) — fines and criminal penalties can apply to both the institution and the individuals involved. The fact is that, not only the sender, but also the recipient should use a secure service to protect the data sent through email.

The Flow

Security at both ends: SSL & MDVault

MDOfficeMail secures the sender's connection with SSL, then hands off to MDVault so the recipient's end is covered too — using VeriSign's RSA-powered SSL/TLS the whole way.

Sender's End

  • Webmail

    SSL establishes an encrypted pipe to MDOfficeMail the moment you connect — well before your username and password are even entered.

  • Outlook & other desktop or mobile clients

    MDOfficeMail only accepts secure ports: 995 (POP), 993 (IMAP), and 465/25 (SMTP), plus AV and spam filtering on every message. Unsecured connections simply aren't allowed.

  • Sent to someone outside MDOfficeMail

    The message is encrypted automatically, stored securely, and a receipt notification is sent — no manual step required.

  • Sent to another MDOfficeMail user

    Delivered directly without the extra MDVault layer, so colleagues aren't stuck decrypting every internal email.

Recipient's End

  • MDOfficeMail user

    The message just shows up like any other email — no password prompt, no extra decryption step.

  • Everyone else: the notification

    The secure message stays in MDVault. The recipient instead gets a short email letting them know a secure message is waiting.

  • Opening it

    Clicking the link opens a secure webpage over SSL. First-time recipients create a password (the sender can share a one-time verification code); after that, the same password unlocks every future message.

  • Reading, replying, saving

    From that same secure window, the recipient can reply securely or download the message to their computer.

Need to send something with no PHI in it?

Type :: anywhere in the subject line and the message goes out plain — handy for quick, non-clinical notes to recipients outside MDOfficeMail. And if a secure message ever goes to the wrong person, the sender can force-expire it so it can no longer be opened.
